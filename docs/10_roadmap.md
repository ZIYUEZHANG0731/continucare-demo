# 10. Roadmap

> **治理提示：** 任何风险分级、Alert KPI 或临床 SLA 都必须在对应规则获批后才能进入实施与测量。当前优先级是 FHIR Profile、术语验证和指标证据治理。

## 1. 路线图原则

产品路线应围绕一个核心闭环逐步扩张：

> Pathway确认 -> 院外随访 -> Observation沉淀 -> 风险分级 -> 医护处理 -> 复诊Summary。

路线图先聚焦单科室、单Pathway和有限接口，优先验证医生是否实际使用复诊前连续健康记忆。

## 2. Phase 0：比赛原型

### 目标

以合成数据展示完整业务闭环、当前实现边界和目标系统设计。

### 范围

- GLP-1治疗Pathway。
- 模拟患者聊天。
- Observation结构化。
- 风险规则触发。
- 护士Risk Center。
- 医生Summary。
- Evidence Trace。
- Safety Guardrail。

### 交付物

- 可点击Demo。
- 技术架构图。
- PRD和系统设计文档。
- 答辩PPT。
- Demo脚本。

### 验收标准

- 患者、护士、医生三端闭环可以稳定演示。
- Observation、Alert、Summary和Evidence Trace能够相互回溯。
- 安全边界、Mock状态和未完成集成有明确标识。
- 目标架构与下一阶段实施范围可以区分。

## 3. Phase 1：MVP

### 目标

验证单科室、单Pathway、复诊前Summary是否能为医生节省时间。

### 范围

- 1个科室。
- 1-3个Pathway。
- 患者Web/H5。
- 医生工作台。
- 护士Alert队列。
- 手动或批量导入患者。
- 只读基础数据，不写回EMR。

### 建议Pathway

1. GLP-1治疗。
2. 高血压复诊管理。
3. 术后恢复。

### 试点指标

- 记录随访完成率及中途退出率，并与试点前人工流程对照。
- 记录医生Summary打开率、审阅率和主观有帮助比例。
- 比较复诊准备耗时和重复追问次数。
- 记录L2以上Alert闭环率、中位闭环时长和超时率。
- 在预定义安全测试集中记录未拦截越界输出率。

具体目标值需在获得科室基线后与试点方共同确定，不在开题阶段预设提升比例。

## 4. Phase 2：医院试点

### 目标

进入真实医院工作流，形成临床和运营指标。

### 范围

- SSO。
- 科室权限。
- 审计日志。
- Pathway审批流。
- HIS/EMR只读集成。
- 短信/微信/院内App消息集成。
- 多角色工作台。

### 新增能力

- Pathway Studio。
- Guideline Agent辅助草案。
- Summary医生反馈学习。
- 质控看板。
- SLA监控。

### 试点验证指标

- 试点前后护士人工随访时间与任务积压量。
- Alert从产生到认领、处置和关闭的时间分布。
- 复诊准备耗时、Summary采纳情况和医生编辑反馈。
- 患者随访完成率、退出率和体验反馈。
- 科室是否愿意审批新增Pathway及其原因。

## 5. Phase 3：医院部署版

### 目标

成为可交付医院客户的生产级系统。

### 范围

- 私有化部署。
- 高可用。
- 数据加密。
- 多科室多Pathway。
- 多租户或医院集团架构。
- 运维监控。
- 接口监控。
- 模型版本管理。
- 安全审计报表。

### 关键补强

- Emergency Workflow生产级通知。
- Alert去重和疲劳控制。
- 患者授权管理。
- 临床治理委员会流程。
- Summary写回EMR审批。

## 6. Phase 4：商业化版本

### 目标

形成可复制销售的连续照护平台。

### 产品方向

- Pathway Library。
- 专科解决方案包。
- 医院集团管理后台。
- 患者长期健康记忆。
- 慢病连续管理。
- 术后恢复管理。
- 质控和运营指标。

### 商业方向

- 按医院/科室订阅。
- 按患者随访量计费。
- 按Pathway模板和实施收费。
- 与医院高端服务包结合。
- 合规条件下开展真实世界数据分析。

## 7. 技术演进路线

| 阶段 | 技术重点 |
|---|---|
| 比赛原型 | 快速Demo、模拟数据、核心闭环 |
| MVP | 稳定数据模型、规则引擎、摘要质量 |
| 试点 | 权限、审计、接口、消息、临床审批 |
| 部署版 | 高可用、安全、私有化、多科室 |
| 商业版 | 模板库、运营分析、规模化实施 |

## 8. 实施所需角色

| 角色 | 职责 |
|---|---|
| 产品负责人 | PRD、临床场景、范围控制 |
| 临床顾问 | Pathway、规则、安全边界 |
| 前端 | 医生工作台、患者端、Demo体验 |
| 后端 | 数据模型、API、规则、任务 |
| AI工程 | Agent、Summary、抽取、Safety |
| 设计 | 信息架构、工作台交互 |
| 商务/项目 | 医院试点、采购与实施协调 |

## 9. 下一阶段实施依赖

- 获得试点科室对Pathway、规则、教育内容和角色责任的审批。
- 完成合成数据评测集、安全测试集和证据完整性检查。
- 明确患者授权、数据最小化、访问控制和审计要求。
- 先完成Aily与飞书适配器的非临床联调，再评估医院旁路接口。
- 真实患者参与前完成机构要求的伦理、法务、信息安全和临床治理流程。

## 10. 最大风险和应对

| 风险 | 应对 |
|---|---|
| 产品范围被理解为AI诊疗 | 在患者端、医生端和技术文档中固定展示“不诊断、不治疗、不改药”边界 |
| 交互停留在聊天展示 | 将Observation、Alert、Timeline、Summary和Evidence Trace作为核心交付链路 |
| 示例规则未经临床验证 | 固定标注合成演示规则，生产规则必须经临床审批和版本管理 |
| 医院接口和流程不确定 | 采用只读旁路、适配器和单科室试点，逐步确认集成范围 |
| 与现有平台能力重叠 | 不以单项功能首创自居，重点验证证据化记忆、共享Agent状态和复诊证据闭环 |
