# ContinuCare Demo 演示脚本

> 全程使用合成患者“陈女士（合成）”。当前版本展示 FHIR 数据底座和可追溯采集，不演示未经审批的临床分级。

## 60–90 秒版本

1. **首页**：说明最终产物是可回溯证据的复诊简报；载入 Questionnaire 驱动的“呕吐与摄入记录”。
2. **患者页**：先展示问题来自锁定的 Questionnaire；按钮和数量答案形成完整 QuestionnaireResponse。“呕吐 1 次”确定性形成 LOINC `94070-0`，“液体摄入 800 mL”形成 LOINC `75301-2`，单位分别为 UCUM `/d` 与 `mL/(24.h)`。
3. **来源链**：展开证据，说明每条 Observation 的 `derivedFrom` 指向原始回答，抽取字符位置不伪装成 FHIR 字段。
4. **规则边界**：指出当前显示“未评估”，因为没有临床批准的报警阈值；系统不会把一次呕吐擅自变成 L2。
5. **医生页与审计页**：生成简报，查看标准化事实、原文证据和医生审阅留痕。

## 2–3 分钟版本

1. **动态条件问题**：选择“有恶心”后，Questionnaire `enableWhen` 显示受控程度选项；选择“无”后该卡片消失，模型不参与按钮生成。
2. **呕吐与摄入记录**：展示两个带 24 小时时间窗的 LOINC Observation 和 UCUM 单位。
3. **仅保留患者原文**：展示未在当前受控术语范围内的文本仍完整保存在 QuestionnaireResponse，但不被错误结构化或自动分级。
4. **治理清单**：打开 `docs/clinical/glp1_14d_observation_evidence.md`，说明每个指标的编码、值类型、时间语义和临床信源。
5. **验证**：说明资源已通过 R4 模型和官方 JSON Schema；医院上线仍须补目标 IG/Profile、术语服务器和临床审批。

## 演示禁语

- 不说“已经完全符合所有医院要求”，只能说“符合 FHIR R4 基础资源结构”；
- 不说“系统诊断为……”或给出调整用药建议；
- 不说旧版 L2/L4 规则仍然生效；
- 不说飞书、Aily、医院术语服务或 EMR 已完成真实联调；
- 不引用真实患者、医院或未经验证的模型效果数字。
