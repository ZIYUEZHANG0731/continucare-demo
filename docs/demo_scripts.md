# ContinuCare 三角色网页演示脚本

> 当前推荐主线：医生端 → 患者端 → 护士端 → 医生端。全程只使用合成身份和合成文本；患者自然语言整理必须已配置火山方舟豆包。Streamlit 旧演示壳不属于本脚本。

## 演示前检查

```bash
.venv/bin/python scripts/mimo_smoke_test.py
npm --prefix patient-web run build
npm --prefix doctor-web run build
.venv/bin/python scripts/start_demo.py --open
```

确认终端显示：

- 患者语义模型已配置；
- 患者/护士服务 `8510` 就绪；
- 医生服务 `8520` 就绪；
- 三端使用同一个 `CONTINUCARE_DB_PATH`。

如需一轮全新的合成演示，停止服务后改用新的数据库文件名，例如 `data/continucare-demo-2.db`，再重新启动；不要删除需要保留的本地记录。

## 90 秒主故事

| 时间 | 页面与操作 | 讲解重点 |
|---|---|---|
| 0–20 秒 | 医生端确认随访内容、频率和周期 | 医生定义照护路径；系统只组合候选，最终方案由医生确认 |
| 20–45 秒 | 患者端勾选合成数据确认，逐题输入并处理候选，最后“确认并提交今天记录” | 豆包只整理待确认候选；患者确认前不写入最终结构化事实 |
| 45–70 秒 | 护士端接收、开始复核，完成清单并选择“上报医生评估” | 软件不自动分诊；处理结果和说明由护士人工给出 |
| 70–90 秒 | 医生端打开“护理协作”，再查看“患者随访” | 医生看到护士明确上报、患者原话、结构化记录和来源，临床评估仍由医生完成 |

精简讲稿：

> 医生先从最小必要电子档案和版本化知识中选择本轮随访内容，确认后才激活患者端。患者用自然语言回答，豆包只把原话整理成待确认卡片，医学代码由本地受控目录绑定；患者最终确认后才形成 QuestionnaireResponse、Observation 和护士任务。护士逐项核对并人工决定是否上报。医生随后在同一记录链中看到护士说明、患者事实和来源证据。系统没有替任何角色作诊断、分诊或治疗决定。

## 完整点击路径

### 1. 医生创建随访方案

地址：<http://127.0.0.1:8520/>

1. 确认右上角为“演示数据”，当前患者为合成患者。
2. 在“本次规划使用的信息”说明系统只读取与当前目标直接相关的最小必要档案。
3. 在“确定本轮记录内容”保留默认记录要点，演示频率可以保持默认。
4. 检查开始和结束日期。
5. 点击右侧确认按钮，等待“随访方案已保存为 v…”提示。
6. 指出方案版本、档案快照、规则版本和引用关系会一起保存；医生仍是最终确认者。

### 2. 患者完成今日随访

地址：<http://127.0.0.1:8510/>

1. 点击“开始今日随访”。
2. 勾选“我确认本次只输入合成演示内容”。每次发送自然语言前都要重新确认；这避免用户无意把真实信息传给外部模型。
3. 按页面当前问题输入合成回答。可使用以下一致的演示数据：体重 65 kg、今天轻度恶心、过去 24 小时呕吐 0 次、饮水约 1500 mL、当前无腹痛。
4. 检查“豆包整理候选”卡片中的原话、含义和数值。需要患者选择的程度必须由患者本人点选。
5. 点击“确认这些内容”；如果页面要求澄清，只选择与刚才合成原话一致的选项。
6. 全部问题完成后，在完整资料卡复核每一项。此时仍是未提交草稿，可以逐项修改或移除补充项。
7. 点击“确认并提交今天记录”，展示记录回执。
8. 强调最终记录来自患者明确确认；无法安全结构化的原话只进入人工复核，不会伪造 Observation。

### 3. 护士人工复核

地址：<http://127.0.0.1:8510/nurse>

1. 在“待处理”队列选择刚生成的任务。
2. 按当前任务按钮依次确认接手并开始人工复核。
3. 阅读“患者确认内容”和患者原话。
4. 逐项勾选完整安全复核清单；软件不会自动勾选。
5. 选择“上报医生评估”。
6. 在“人工复核说明”填写合成说明，例如：“已核对患者确认记录与原话，请医生结合复诊计划进一步评估。”
7. 点击“保存护士人工决定”。
8. 指出“上报医生”是护士的人工工作流决定，不代表系统已判断风险或完成临床评估。

### 4. 医生查看上报与随访资料

回到 <http://127.0.0.1:8520/>：

1. 点击顶部“协作”或左侧“护理协作”。
2. 展示“护士上报待办”、护士人工说明和患者已确认回答。
3. 读出页面边界：“临床评估状态：未评估 · 需由医生本人判断”。
4. 切换到“观察”，展示随访摘要、近期指标和数据来源。
5. 刷新页面，确认状态仍可从 SQLite 事实恢复。

## 失败恢复

- **患者端显示等待医生**：先到医生端确认方案，再刷新患者端。
- **患者端显示豆包未配置**：检查 `.env`，运行 `scripts/mimo_smoke_test.py`；不要声称已完成模型链路。
- **豆包结果未通过安全校验**：原记录保持不变；重新确认只使用合成数据后再发送，必要时停止演示并检查配置。
- **护士端没有任务**：确认患者已点击“确认并提交今天记录”，然后刷新护士端。
- **医生端没有协作待办**：确认护士选择的是“上报医生评估”并已保存，而不是“未上报医生”。
- **三端状态不一致**：停止服务，确认三端使用同一 `CONTINUCARE_DB_PATH`，再用统一启动器启动。
- **端口占用**：停止旧的启动进程，不要同时运行两组主线服务。

## 演示禁语

- 不说“已接入真实医院、EMR、飞书或 Aily”；
- 不说“系统已诊断、自动分诊、自动预警或决定治疗”；
- 不说“豆包生成了医学代码”；医学代码来自版本化本地受控映射；
- 不说“上报医生”等于完成临床评估；
- 不说“消息已真实发送”；当前外部适配器保持 Mock/disabled；
- 不把工程测试通过率描述为临床准确率；
- 不输入、截图或提交真实患者信息与 API Key。
